## What Are Logs?

A **log** is a record of activity generated by a computer, application, server, network device, or other system.

A simple way to understand logs is to think of them as **digital footprints**.

For example, when a user logs into a computer, an application encounters an error, a firewall blocks a connection, or a web server receives a request, the system may record that activity in a log.

These records can later be examined to answer important investigation questions such as:

**What happened? When did it happen? Which account or system was involved? What action occurred? Where did the activity come from?**

This makes logs extremely valuable for security monitoring and incident investigation.

---

## Why Are Logs Important in Cybersecurity?

Attackers often attempt to avoid detection and remove evidence of their actions. However, their interaction with a system can still produce multiple traces.

Security teams can analyze these traces to understand the sequence of events.

For example, imagine that a server has been compromised. Investigators may discover:

* A successful login.
* Several failed login attempts before it.
* A newly created user account.
* A password reset.
* Access to sensitive files.
* Network connections to an unusual destination.

Individually, these events may not provide the complete story. When combined and analyzed in the correct order, they can help investigators reconstruct what happened.

This is why logs are often treated as an important source of **digital evidence**.

---

## Common Uses of Logs

Logs have many uses beyond security investigations.

### Security Monitoring

Security teams can monitor logs for suspicious activity, unusual authentication attempts, unexpected network connections, and other indicators of compromise.

### Incident Investigation

During an incident, analysts can use logs to determine what happened, when it happened, which systems were affected, and potentially how the attacker gained access.

### Troubleshooting

Applications and operating systems can record errors and warnings in logs. Engineers can use this information to diagnose technical problems.

### Performance Monitoring

Logs can provide information that helps identify performance-related problems such as excessive resource usage or application failures.

### Auditing and Compliance

Organizations can maintain records of important actions such as user activity, file access, configuration changes, and account modifications.

# Types of Logs

Different systems generate different kinds of logs. The exact categories can vary between technologies, but several major types are commonly encountered.

## 1. System Logs

System logs record operating-system-level activity.

Examples include:

* System startup.
* System shutdown.
* Operating-system events.
* Hardware-related problems.
* System-level errors.

System logs can help determine whether a problem occurred at the operating-system or hardware level.

---

## 2. Security Logs

Security logs record security-related activity, especially authentication and account-related events.

Examples include:

* Successful logins.
* Failed login attempts.
* Logouts.
* Account changes.
* Authentication events.
* Authorization-related activity.

These logs are particularly useful during investigations involving unauthorized access or brute-force attempts.

For example, Windows Event ID **4624** represents a successful logon, while Event ID **4625** represents a failed logon.

A large number of failed authentication attempts may indicate password guessing or brute-force activity, although the surrounding context must always be investigated before making a conclusion.

---

## 3. Application Logs

Application logs are generated by software and applications.

They may contain:

* Errors.
* Warnings.
* Successful operations.
* Database connection problems.
* Application-specific events.
* Resource or performance information.

Application logs are useful when investigating problems that occur inside a specific application rather than the operating system itself.

---

## 4. Audit Logs

Audit logs record actions performed within a system.

They can answer questions such as:

**Who performed an action? What action was performed? When was it performed?**

Examples include:

* File deletion.
* Password changes.
* Configuration changes.
* Data access.
* User activity.

Audit logs are valuable because they create a historical record of important actions.

---

## 5. Network Logs

Network logs record network-related activity.

They may contain information such as:

* Source IP address.
* Destination IP address.
* Source or destination port.
* Protocol.
* Action taken.
* Connection information.

Firewall logs are a common example of network logs.

For example, a firewall log might show that traffic from one IP address to TCP port 22 was blocked. Port 22 is commonly associated with SSH.

---

## 6. Access Logs

Access logs record requests made to resources.

They are commonly found in:

* Web servers.
* APIs.
* Databases.
* Applications.

A web server access log may show:

* Client IP address.
* Timestamp.
* HTTP method.
* Requested URL.
* HTTP status code.
* User-Agent.

This information can be used to understand how a web application or website is being accessed.

# Understanding Windows Event Logs

Windows provides a built-in graphical tool called **Event Viewer** for viewing and investigating event logs.

The important Windows log categories introduced in this room include:

* Application
* Security
* System

Additional log categories can also exist depending on the Windows configuration and services installed on the system.

---

## Windows Event Viewer

Event Viewer allows an analyst to:

* Browse events.
* Read event details.
* Filter events.
* Search for specific events.
* Inspect event properties.
* Create custom views.

A large Windows log can contain thousands of events, so filtering is extremely important during an investigation.

Instead of manually reading every event, an analyst can filter the log using an **Event ID** or other criteria.

---

# Understanding Event IDs

A Windows Event ID is an identifier associated with a particular type of event.

Some important Event IDs encountered in the room include:

| Event ID | Meaning                                   |
| -------- | ----------------------------------------- |
| 4624     | Successful logon                          |
| 4625     | Failed logon                              |
| 4634     | Logoff                                    |
| 4720     | User account created                      |
| 4722     | User account enabled                      |
| 4724     | Attempt made to reset an account password |

Event IDs allow analysts to quickly locate specific types of activity.

For example, if an investigation asks:

> Which user account was created most recently?

Filtering the Security log for **Event ID 4720** can reduce thousands of events to only the events related to user-account creation.

# Practical Windows Event Log Investigation

One of the practical investigations in the room involved a compromised system.

The organization discovered that critical data had been taken from a file server. Investigators already knew the compromised system and needed to determine what the attacker did before accessing the file server.

The investigation involved examining Windows Security Events.

### Finding the Last Created User Account

A newly created user account can be suspicious, especially when it appears during or around an intrusion.

The room used:

**Event ID 4720 – User account created**

By filtering the Security log for this Event ID, the relevant account-creation events could be identified.

The newest event revealed the most recently created account.

The investigation also showed which account performed the creation.

### Checking Whether the Account Was Enabled

The room then examined:

**Event ID 4722 – User account enabled**

This allowed the analyst to determine when the newly created account became enabled.

### Checking for a Password Reset

The investigation also examined:

**Event ID 4724 – Attempt made to reset an account's password**

This helped determine whether a password reset action had occurred for the account.

This demonstrates an important investigation principle:

**Do not analyze one event in isolation. Connect related events together to reconstruct the sequence of actions.**

# Web Server Access Logs

Web servers record incoming HTTP requests in access logs.

A request can look conceptually similar to:

```text
IP_ADDRESS TIMESTAMP "HTTP_METHOD URL" STATUS_CODE "USER_AGENT"
```

The exact format depends on the web server and its logging configuration.

---

## Important Fields in Web Access Logs

### IP Address

The IP address identifies the source of the request as recorded by the web server.

This can help investigators identify where requests came from.

### Timestamp

The timestamp shows when the request occurred.

Timestamps are extremely important when reconstructing the timeline of an incident.

### HTTP Method

The HTTP method indicates what type of request was made.

Common methods include:

* GET
* POST

A **GET** request is commonly used to retrieve a resource.

A **POST** request is commonly used to send data to a server, such as form data.

### Requested URL

The URL shows which resource was requested.

For example:

```text
/contact
```

or:

```text
/login
```

### HTTP Status Code

The status code describes the server's response.

Some important examples are:

| Status Code | Meaning             |
| ----------- | ------------------- |
| 200         | Successful response |
| 401         | Unauthorized        |
| 403         | Forbidden           |
| 404         | Resource not found  |

Status codes can provide useful clues during web investigations.

### User-Agent

The User-Agent can provide information about the client making the request, such as the browser or operating system.

# Basic Web Log Analysis

The room demonstrated basic command-line techniques for manually analyzing access logs.

These commands are useful for understanding the fundamentals even though real-world SOC environments often use centralized log platforms and dashboards.

---

## `cat`

The `cat` command displays the contents of a text file.

Example:

```bash
cat access.log
```

This is useful when you want to quickly view the contents of a log file.

---

## Combining Log Files

Logs are often rotated.

For example:

```text
access1.log
access2.log
```

may contain different periods of logging.

The room demonstrated how multiple files can be combined:

```bash
cat access1.log access2.log > combined_access.log
```

Here:

* `cat` reads the files.
* `>` redirects the output.
* `combined_access.log` stores the combined content.

This creates a single file containing the contents of both logs.

---

## `grep`

`grep` can search for a specific pattern inside a file.

Example:

```bash
grep "192.168.1.10" access.log
```

This displays lines containing the specified IP address.

It is especially useful when a log file is large and you need to find only events related to a specific value.

For example:

```bash
grep "GET /contact" access.log
```

can help locate requests made to `/contact`.

---

## `less`

The `less` command allows you to read large files page by page.

Example:

```bash
less access.log
```

Useful navigation includes:

* `Space` → next page
* `b` → previous page
* `/pattern` → search for a pattern
* `n` → next search result
* `N` → previous search result

This can be more practical than using `cat` when the file is very large.

# Practical Web Log Investigation

The practical task provided a sample web server access log.

The investigation required finding information related to requests made to specific URLs.

For example, to identify requests to `/contact`, a search pattern can be used:

```bash
grep "GET /contact" access.log
```

The returned entries can then be compared using their timestamps.

The **latest timestamp** identifies the most recent matching request.

Similarly, searching for an IP address can reveal all recorded requests associated with that IP:

```bash
grep "172.16.0.1" access.log
```

This demonstrates a basic but important investigation workflow:

**Filter → identify relevant events → compare timestamps → reconstruct activity.**

# Investigation Mindset

The most important lesson from this room is that log analysis is not simply about reading text.

An analyst needs to ask questions.

For example:

**Who performed the action?**

Look for account names, usernames, or source IP addresses.

**What happened?**

Look at the event description, HTTP method, action, status code, or Event ID.

**When did it happen?**

Use timestamps to build a timeline.

**Where did it come from?**

Investigate source IP addresses, systems, or other available identifiers.

**What happened before and after it?**

Correlate multiple events rather than analyzing one line independently.

This approach helps transform individual log entries into a larger incident story.

# Key Takeaways

Logs are one of the most important sources of evidence available to defenders.

Different log types provide different kinds of information. Security logs are particularly useful for authentication and account-related investigations, while network logs, application logs, audit logs, system logs, and access logs provide different pieces of the overall picture.

Windows Event Viewer provides a graphical interface for inspecting Windows logs, and Event IDs make it possible to locate specific types of events efficiently.

Web server access logs contain valuable information such as source IP addresses, timestamps, HTTP methods, URLs, status codes, and User-Agent strings.

Command-line tools such as `cat`, `grep`, and `less` provide simple ways to inspect and search log files.

The most important investigation skill is **correlation**. A single event may not tell the whole story, but several related events can reveal an attacker's actions and help reconstruct an incident timeline.

# Beginner Practice Ideas

After completing the room, a beginner can strengthen these concepts by performing small investigations.

Create a simple test environment and generate normal activities such as logging in, logging out, creating a user, enabling an account, and changing a password. Then open Event Viewer and attempt to find the corresponding events.

For web logs, create or use a sample access log and practice finding all requests from one IP address, all requests to one URL, all failed responses, and the latest request to a specific endpoint.

The goal is to stop relying on memorization and instead become comfortable with the investigation process:

**Find the relevant log source → filter the data → understand the fields → compare timestamps → connect the events → build the story.**
