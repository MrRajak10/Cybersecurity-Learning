## 1. The Core of Network Security: IDS vs. IPS

To secure a network, you must have visibility into the traffic entering, leaving, and moving around inside it. This is where Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) come in.

### Intrusion Detection System (IDS)

* **What it is:** A passive monitoring system that watches network traffic for suspicious or malicious activity.
* **How it works internally:** An IDS is usually connected to a "SPAN port" or a "network tap." This means a *copy* of the network traffic is sent to the IDS. It is not in the direct path of the data.
* **What problem it solves:** It gives security teams visibility (logs and alerts) into what is happening on the network without slowing down the actual flow of business traffic.
* **Analogy:** An IDS is like a security camera operator in a casino. They can see someone cheating and alert the floor manager, but they cannot physically stop the cheater from across the room.

### Intrusion Prevention System (IPS)

* **What it is:** An active security device that can both monitor traffic and take immediate action to block malicious activity.
* **How it works internally:** An IPS is placed **inline**. This means the physical network cable goes *into* the IPS, and another cable goes *out* to the rest of the network. Every single packet must pass through it.
* **What problem it solves:** It provides automated defense, stopping attacks before they reach the target server.
* **Analogy:** An IPS is the bouncer at the door of a club. They check every ID (packet). If someone is on the banned list, the bouncer physically blocks them from entering.

> **Why Security Professionals Care:**
> * **SOC Analysts:** Spend their days reviewing the alerts generated by the IDS to determine if an attack was successful.
> * **Penetration Testers:** Need to know if an IPS is present. If they send a loud, obvious exploit through an IPS, their IP address will be instantly blocked, ending their attack simulation prematurely.

## 2. How Security Systems "Think": Detection Methods

How does an IDS or IPS actually know if a packet is evil? They use two primary methods of logic.

### Signature-Based Detection

* **What it is:** The system compares incoming network traffic against a database of known malicious patterns (signatures).
* **How it works:** If a hacker uses a known exploit (like EternalBlue), that exploit sends a very specific sequence of bytes over the network. Security researchers create a "signature" for this exact byte sequence. If the IDS sees it, it triggers an alert.
* **Analogy:** This is exactly like a "Wanted" poster. The police (IDS) look at the face of everyone walking by. If someone matches the poster exactly, they are flagged.
* **The Flaw:** If the attacker wears a fake mustache (modifies their attack slightly), they no longer match the "Wanted" poster, and the IDS lets them right through.

### Anomaly-Based Detection

* **What it is:** The system establishes a "baseline" of what normal network traffic looks like, and flags anything that deviates from that baseline.
* **How it works:** The IDS spends a week learning that User A usually logs in at 9:00 AM from New York and downloads 5MB of data. If User A suddenly logs in at 3:00 AM from Russia and tries to download 50GB of data, the IDS flags it as an anomaly.
* **Analogy:** Your bank's credit card fraud department. They know your spending habits. If you suddenly try to buy ten televisions in another country, they freeze the card because it is highly unusual, even if buying a TV isn't inherently "malicious."

## 3. The Anatomy of an IDS/IPS Rule (e.g., Snort)

**Snort** is the most famous open-source network intrusion detection system in the world. When you write a rule for Snort (or similar systems), you are teaching it a new signature.

A rule reads like a logical sentence:
`Action + Protocol + Source IP/Port + Direction + Destination IP/Port + Options`

Let's break down a real-world example of an IPS blocking malicious ICMP (ping) traffic:
**`drop icmp any any -> 192.168.1.50 any (msg:"Malicious Ping Detected"; sid:10001;)`**

* **drop (Action):** The IPS will destroy the packet.
* **icmp (Protocol):** The rule only looks at ICMP traffic.
* **any any (Source):** Coming from *any* IP address and *any* source port.
* **-> (Direction):** Traffic moving toward the destination.
* **192.168.1.50 any (Destination):** Going to this specific web server, on any port.
* **Options:** `msg` is the alert text the SOC analyst will see. `sid` is the unique Signature ID.

> **Common Beginner Mistake:** Memorizing exact syntax rather than the logic. If you understand the *Who -> What Protocol -> To Whom* logic, you can easily adapt to any security tool, whether it is Snort, Suricata, or a cloud firewall.

## 4. The Art of Evasion: Hiding in Plain Sight

If defenders have an IPS, how do attackers ever win? They use **Evasion Techniques**.

Evasion is the practice of manipulating network traffic so that it completes the attacker's goal but bypasses the IDS/IPS signatures. We categorize these into Protocol Manipulation and Payload Manipulation.

### Protocol Manipulation

This involves messing with the "envelope" of the message—the TCP/IP headers.

**1. Source Port Manipulation**

* **The Concept:** Firewalls often trust traffic coming from specific ports (like DNS port 53 or HTTP port 80).
* **The Attack:** An attacker can use a tool to manually change their source port to 53. The firewall looks at it and thinks, "Oh, this is just a DNS response, I'll let it through," even though the attacker is actually sending a reverse shell.
* **Tool - Nmap (`-g` flag):** **Nmap** is a network scanner used to discover hosts and open ports. The `-g` option allows a pentester to force Nmap to send all its scan packets from a specific port (like port 80) to trick simple firewalls.

**2. Session Splicing & Fragmentation**

* **The Concept:** Instead of sending the malicious payload in one big packet, the attacker chops it up into tiny pieces.
* **Analogy:** Imagine trying to send a prohibited book into a prison. If you send the whole book, the guards (IDS) seize it. But if you tear out the pages and mail one page per day over a year, the guards might not realize what the text is.
* **The Defense:** Modern security tools use "Stream Reassembly." The IDS holds all the pieces in memory, tapes the book back together, reads it, and *then* decides if it is malicious.

**3. TCP Flag Manipulation & Invalid Checksums**

* **The Concept:** TCP communication uses "flags" (SYN, ACK, FIN) to establish connections. Attackers can send packets with impossible combinations of flags (e.g., saying "Hello" and "Goodbye" at the exact same time).
* **Why it works:** The IDS might get confused by the invalid packet and drop it from inspection, but the target server might accept it and process the payload. This discrepancy creates a blind spot.

### Payload Manipulation

This involves messing with the "letter" inside the envelope—the actual data being sent.

**1. Encoding (Not Security!)**

* **What it is:** Translating data into a different format for safe transport. **Base64** and **URL Encoding** are the most common.
* **How it works:** The command `cat /etc/passwd` encoded in Base64 looks like `Y2F0IC9ldGMvcGFzc3dk`.
* **Why Attackers use it:** If the IDS has a signature looking for the exact text `cat /etc/passwd`, it will completely miss the Base64 version.
* **Crucial Rule:** *Encoding is not encryption.* There is no password or key needed to decode Base64. Anyone who sees it can reverse it instantly.

**2. Encryption (True Security, True Headache)**

* **What it is:** Scrambling data using complex mathematics and a secret key. Without the key, the data is unreadable.
* **Tool - OpenSSL & Ncat:**
* **OpenSSL:** A robust toolkit for generating cryptographic keys and certificates.
* **Ncat:** Often called the "Swiss Army Knife" of networking. It can read, write, and redirect data across networks. Attackers use Ncat combined with OpenSSL to create encrypted reverse shells.


* **The Blue Team Problem:** If an attacker encrypts their traffic, the IDS just sees a stream of randomized garbage. It cannot inspect the payload for signatures. To combat this, modern enterprise networks perform "SSL Decryption" (Man-in-the-Middle) where the firewall decrypts the traffic, inspects it, re-encrypts it, and sends it to the user.

## 5. Routing Manipulation and Tactical Evasion

**Proxy Servers**

* **What it is:** A middleman server.
* **How it works:** Instead of the attacker's computer connecting directly to the target, the attacker connects to the proxy, and the proxy connects to the target.
* **Why it matters in Incident Response:** If a SOC analyst looks at the firewall logs and sees an attack coming from IP `198.51.100.5`, they might try to block it. But if that IP belongs to a proxy (like an anonymous VPN or Tor node), they haven't blocked the attacker; they've only blocked the middleman. The attacker will just switch to a new proxy in seconds.

**Tactical Denial of Service (DoS)**

* **What it is:** Overwhelming the security device itself.
* **How it works:** If an attacker wants to sneak a payload past an IPS, they might first send 10 gigabits of junk traffic directly at the IPS.
* **Why it works:** To prevent the entire company's internet from crashing, many IPS devices are designed to "fail open." This means if their CPU hits 100% and they can't inspect traffic fast enough, they simply turn off inspection and let everything through. The attacker sends their real payload during this window.

## 6. The Modern Era: Next-Generation Firewalls (NGFW)

Older firewalls only looked at Ports and IP addresses (Layer 3 and 4 of the OSI model).
Older IPS systems only looked for static signatures.

**Next-Generation Firewalls (NGFW)** (like Palo Alto or Fortinet) combine everything into one powerful box.

* They don't just see "Port 80"; they see "User Bob is using the Google Chrome application to access Facebook."
* They integrate deep packet inspection, threat intelligence feeds, active sandboxing (detonating suspicious files in a virtual environment), and anomaly detection.
